# 文档与维护审查实施计划

> 面向协作者：按复选框逐项完成。每一组修改都要用对应的测试、静态检查或链接检查验证。

**目标：** 让当前仓库的说明、测试入口和质量检查准确反映已实现功能，并降低新人上手和团队维护成本。

**架构：** 根 README 负责项目导航和当前状态。应用与 package README 负责快速开始。复杂接口、部署、数据契约和运行故障说明放在各自的 `docs/` 中。历史计划和设计文档保留历史上下文，不作为当前状态页面。

**技术栈：** Markdown、Python、pytest、Ruff、ty、coverage、pip-audit、npm、TypeScript、GitHub Actions。

**规范：** 中文正文使用中文标点和直接表达。命令、路径、代码标识符、schema 名称和必要的技术名词保留原样。当前事实以代码、配置和现行 workflow 为准。

## 全局约束

- 当前仓库不使用 Git submodule，外部数据项目通过文件、API 或 artifact 契约协作。
- 不删除历史设计、迁移记录或兼容入口，除非先确认仓库内外调用方。
- 不把样例快照、历史测试结果或 workflow 定义写成生产证据。
- README 保留最短可用路径，技术细节进入对应 `docs/` 文件。
